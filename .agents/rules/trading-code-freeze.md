# Code Freeze During Trading Operations

Applies whenever the session does trading work: market scans or analysis, evaluator runs, opening/managing/closing positions, publishing or reporting positions, journaling.

- **The repository is read-only for you during trading work.** Never create, edit, move or delete repo files (`scripts/`, `tests/`, `.agents/`, `.claude/`, `AGENTS.md`, `CLAUDE.md`, `README.md`, `docs/`, `config/*.example`, hooks), never run `git commit/checkout/reset/stash/push/merge`, never install or upgrade dependencies, and never write ad-hoc scripts that replicate or patch desk logic. Runtime outputs written by the desk scripts themselves (`logs/`) are expected.
- **The code is tested and production-ready.** If a script fails, a gate behaves unexpectedly, output is malformed, or a hook denial looks like a bug: stop that step (fail closed — no retries with variations, no workarounds), keep open positions protected using only the sanctioned risk-reducing CLI (`scripts/execute_futures_trade.py --close-position | --move-breakeven --symbol X | --auto-heal`, `scripts/loops/position_guardian_loop.py --once`), and open a GitHub issue:
  `./scripts/report_issue.sh --title "<script>: <short failure>" --error "<exact error message>" --category tool_error|risk_gate|infra|agent_failure --severity CRITICAL|HIGH|MEDIUM|LOW [--priority P0|P1|P2|P3] --repro "<exact command> (exit <code>)" --root-cause "<suspected cause>" --affected-files "<path:lines, ...>" --context "<what you were doing and observed>" [--context-file <notes file>] --output-file logs/issue_output_<unix_ts>.log --impact "<effect on the desk>" --acceptance-criteria "<criterion; criterion>" --remediation "<suggested fix>"`
  (offline, it queues to `logs/issues_backlog.jsonl`). Always pass `--severity` (and `--priority` only when it differs from the default) and every structured flag you have evidence for; never invent values (omit a flag rather than guess a root cause, code pointer or file). The script adds git/env/ledger telemetry (no amounts) and the `severity:*` / `priority:*` labels. If you ever create an issue with `gh issue create` directly, label it too: `--label severity:<x> --label priority:<Px>`. Write raw output you already have (never re-run a failing command to capture it) to `logs/issue_output_<unix_ts>.log`, the one file you may write during trading work, and pass it with `--output-file`; the pre-trade hook classifies the whole command text, so when the failing command is `scripts/execute_futures_trade.py` put the exact command and its output in that file and keep `--repro` to the script name and exit code. Report quant values as key/value pairs (`t_stat=-3.42`, `z=-2.15`, `beta=+0.87`) so the sanitizer keeps them; amounts and other bare signed decimals are redacted. Attachments naming credential files (`.env`, `*.env`, `.mcp.json`, `mcp_config*`, `*credentials*`, `*.pem`, `*.key`) are refused with exit 2. Give the user the issue link and continue only with steps the failure does not affect.
- **Severity:** CRITICAL = a position is unprotected or its stop cannot be verified; HIGH = execution or a gate is blocked; MEDIUM = scan/analysis degraded; LOW = cosmetic. Default priority: CRITICAL → P0, HIGH → P1, MEDIUM → P2, LOW → P3 (pass `--priority` only to override).
- **Fixes are a separate development task:** only when the user explicitly asks to fix an issue, on a feature branch with tests and a PR — never mixed into a trading session.
